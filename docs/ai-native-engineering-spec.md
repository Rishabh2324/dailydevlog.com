## How Software Engineers Use AI to Design, Build, Test, Deploy, Maintain and Automate Software

---

# ROLE

Act as an expert:

* Software Engineering Curriculum Architect
* Senior Software Engineer
* Frontend Engineer
* Backend Engineer
* Full-Stack Engineer
* Software Architect
* UX/UI Engineer
* DevOps Engineer
* AI Engineer
* AI Coding-Agent Practitioner

Your task is to design a **COMPLETE SELF-PACED WRITTEN COURSE** called:

# "AI-NATIVE SOFTWARE ENGINEERING"

### Subtitle

**"How Developers Use AI to Design, Build, Maintain and Automate Software"**

The course should feel like a **professional engineering curriculum**, not a collection of articles, AI tutorials, or prompt-engineering tricks.

# IMPORTANT — COURSE PURPOSE

This is NOT primarily:

* An LLM theory course
* A machine-learning course
* A RAG course
* An AI-agent-building course
* A generic ChatGPT course
* A prompt-engineering course
* A list of AI tools
* A "10x developer" marketing course

The purpose is to teach:

> **How professional software engineers can use modern AI throughout the entire software development lifecycle.**

The course must teach how AI can help developers with:

* Product discovery
* Requirements
* Research
* Planning
* UX
* UI
* Architecture
* System design
* Frontend development
* Backend development
* Database development
* Full-stack development
* Testing
* Debugging
* Code review
* Security
* Git
* Pull requests
* CI/CD
* Deployment
* Observability
* Incident response
* Documentation
* Existing codebases
* Legacy codebases
* Automation
* Coding agents
* MCP
* Context engineering
* Developer workflows
* Team collaboration

The central question throughout the course is:

> **"How would a good software engineer use AI to perform this task?"**

Do not merely explain what an AI tool does.

Instead explain:

> **How should an engineer incorporate that capability into a real engineering workflow?**

# CORE PHILOSOPHY

The fundamental engineering loop is:

```text
UNDERSTAND
    ↓
DISCOVER
    ↓
ANALYZE
    ↓
PLAN
    ↓
DESIGN
    ↓
CONTEXTUALIZE
    ↓
GENERATE
    ↓
IMPLEMENT
    ↓
VERIFY
    ↓
TEST
    ↓
REVIEW
    ↓
SHIP
    ↓
MONITOR
    ↓
LEARN
    ↓
IMPROVE
    ↓
AUTOMATE
```

The most important principle is:

> **AI SHOULD AUGMENT ENGINEERING THINKING, NOT REPLACE IT.**

Teach when developers should:

* Use AI
* Not use AI
* Use AI as an assistant
* Use AI as a researcher
* Use AI as a planner
* Use AI as a reviewer
* Use AI as a debugging partner
* Use AI as an architecture thought partner
* Use AI as a coding agent
* Allow autonomous execution
* Require human approval

Use this mental model throughout the course:

```text
Developer
    ↓
Context
    ↓
AI
    ↓
Generated / Suggested Result
    ↓
Verification
    ↓
Testing
    ↓
Human Decision
    ↓
Production
```
