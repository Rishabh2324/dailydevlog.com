## 1. Restate the problem

Given a sorted array `arr` where every element appears exactly twice except for one element which appears exactly once, find and return that single element.

## 2. Inputs, outputs, edge cases

- **Input:** `arr`, a sorted array of integers, `1 <= arr.length <= 10^5`, where exactly one value appears once and every other value appears exactly twice.
- **Output:** the single non-duplicated value.
- **Constraints noted:**
  - Array length is always **odd** (pairs take up an even count, plus one single element).
  - Must run faster than a linear scan (the expected solution is `O(log n)`).
  - Single-element array (`arr.length === 1`) → that one element is trivially the answer.
  - The single element can sit at the very start, the very end, or anywhere in the middle of the array.

## 3. Work a small example by hand — "find the left and right pair which is odd"

`arr = [1,1,2,3,3,4,4,8,8]` — the single element is `2` at index `2`.

The key insight: before the single element, every pair starts at an **even** index (`(0,1)`, then the single at `2`, then pairs starting at `3`, `5`, `7`...). So wherever you land on a pair, you can check whether the segment *before* that pair has an even or odd length — an even-length segment before the pair means the single element is still ahead (to the right); an odd-length segment means the single element already came before this pair (to the left).

| low | high | mid | arr[mid] | pair found? | segment before pair | parity | action |
|-----|------|-----|----------|-------------|----------------------|--------|--------|
| 0 | 8 | 4 | 3 | `arr[4]==arr[3]` (pair at `3,4`) | indices `0..2`, length `3` | odd | single is before this pair → `high = mid - 2 = 2` |
| 0 | 2 | 1 | 1 | `arr[1]==arr[0]` (pair at `0,1`) | indices before `0`, length `0` | even | single is after this pair → `low = mid + 1 = 2` |
| 2 | 2 | 2 | 2 | no match on either side | — | — | return `arr[2] = 2` |

Result: `2` ✓.

## 4. Brute force first

Scan pairs two at a time; the first index where the expected pair breaks is (or lands on) the single element.

```ts
function singleNonDuplicateBruteForce(arr: number[]): number {
  for (let i = 0; i < arr.length - 1; i += 2) {
    if (arr[i] !== arr[i + 1]) return arr[i];
  }
  return arr[arr.length - 1];
}
```

- **Time:** `O(n)` — walks pairwise through the array until the mismatch, which is correct but not the expected `O(log n)`.
- **Space:** `O(1)`.

## 5. Identify the pattern and optimize

Because every element before the single one pairs up starting at an even index, the **parity of the segment length before any landed-on pair** tells you which side of the array the single element is on — no need to scan pair by pair. At a binary search midpoint `mid`, check whether `mid` is part of a pair with its left neighbor (`arr[mid] === arr[mid-1]`) or right neighbor (`arr[mid] === arr[mid+1]`); once you've located a pair, measure how many elements sit before it. If that count is odd, an unpaired element has already thrown off the "pairs start on even indices" alignment somewhere to the left, so the single element is in `[low, pairStart - 1]`; if even, the alignment is still intact up to here, so the single element is in `[pairStart + 2, high]`. This collapses the search from `O(n)` to `O(log n)`.

## 6. Code it

```ts
function singleNonDuplicate(arr: number[]): number {
  let low = 0;
  let high = arr.length - 1;

  if (arr.length === 1) return arr[0];

  while (low <= high) {
    const mid = low + Math.floor((high - low) / 2);

    if (arr[mid] === arr[mid - 1]) {
      if ((mid - 1 - low) % 2 !== 0) {
        high = mid - 2;
      } else {
        low = mid + 1;
      }
    } else if (arr[mid] === arr[mid + 1]) {
      if ((high - (mid + 1)) % 2 !== 0) {
        low = mid + 2;
      } else {
        high = mid - 1;
      }
    } else {
      return arr[mid];
    }
  }

  return arr[low];
}
```

## 7. Test it manually

- `arr = [1,1,2,3,3,4,4,8,8]` → traced in step 3 → `2` ✓
- `arr = [2,3,3,4,4]` (single at the start) → `low=0,high=4`; `mid=2`, `arr[2]=3 === arr[1]=3` → segment before pair length `mid-1-low=1`, odd → `high = mid-2 = 0`; `low=0,high=0`; `mid=0`, no left/right match → returns `arr[0]=2` ✓
- `arr = [1,1,2,2,3]` (single at the end) → `low=0,high=4`; `mid=2`, `arr[2]=2 === arr[3]=2` → segment after pair length `high-(mid+1)=4-3=1`, odd → `low = mid+2 = 4`; `low=4,high=4`; `mid=4`, no match → returns `arr[4]=3` ✓
- `arr = [5]` (single-element array) → guard clause (`arr.length === 1`) → returns `5` ✓

## 8. Review and log

- **Approach used:** binary search using the parity of the segment length before/after a located pair to decide whether the single element lies to the left or right, instead of comparing absolute element values.
- **Mistake to watch for:** jumping by `mid + 1`/`mid - 1` after finding a pair (treating it like a normal binary search hit) skips over the pair incorrectly — since a pair occupies two indices, the next search range must skip both (`mid + 2` or `mid - 2`) to avoid re-landing inside the same pair.
- **Recurring pattern to log:** "binary search on index parity relative to a known invariant" generalizes to problems where sorted/paired structure creates an alignment that breaks exactly once — similar in spirit to the boundary-seeking binary searches in [[find-minimum-in-rotated-sorted-array]] and [[find-k-closest-elements]], but here the signal is parity rather than value comparison.

## Complexity

- **Time:** `O(log n)` — binary search halves the candidate range each iteration.
- **Space:** `O(1)` — a fixed number of pointer variables.
