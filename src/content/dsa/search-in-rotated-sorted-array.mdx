## 1. Restate the problem

Given an integer array `nums` sorted in ascending order with **distinct** values, which has been rotated at some unknown pivot (e.g. `[0,1,2,4,5,6,7]` might become `[4,5,6,7,0,1,2]`), and a `target` value, return the index of `target` in `nums` if it exists, otherwise return `-1`.

## 2. Inputs, outputs, edge cases

- **Input:** `nums`, an array of `1 <= nums.length <= 5000` **distinct** integers, originally sorted ascending then rotated at an unknown pivot; `target`, an integer.
- **Output:** the index of `target` in `nums`, or `-1` if not present.
- **Constraints noted:**
  - Must run in `O(log n)` — a linear scan is not the intended solution.
  - All values are distinct (no duplicates to worry about).
  - The array may not be rotated at all (pivot at index `0`) — must still work as plain binary search.
  - Single-element array → either matches target or doesn't.
  - `target` not present anywhere → `-1`.
  - `target` at the pivot boundary (the smallest or largest element).

## 3. Work a small example by hand

`nums = [4,5,6,7,0,1,2]`, `target = 0`

| low | high | mid | nums[mid] | which half is sorted? | action |
|-----|------|-----|-----------|------------------------|--------|
| 0 | 6 | 3 | 7 | `nums[low]=4 <= nums[mid]=7` → left half `[4..7]` sorted | `target=0` not in `[4,7]` → search right: `low=4` |
| 4 | 6 | 5 | 1 | `nums[low]=0 <= nums[mid]=1` → left half `[0,1]` sorted | `target=0` is in `[0,1]` → search left: `high=4` |
| 4 | 4 | 4 | 0 | `nums[mid] === target` | found → return `4` |

Result: index `4` ✓ (`nums[4] = 0`).

## 4. Brute force first

Scan the array linearly for the target.

```ts
function searchBruteForce(nums: number[], target: number): number {
  for (let i = 0; i < nums.length; i++) {
    if (nums[i] === target) return i;
  }
  return -1;
}
```

- **Time:** `O(n)` — checks every element in the worst case, which violates the required `O(log n)` bound.
- **Space:** `O(1)`.

## 5. Identify the pattern and optimize

The array isn't fully sorted, but it's made of **two sorted halves** glued together at the rotation point. At any midpoint, at least one of the two halves (`[low..mid]` or `[mid..high]`) is guaranteed to be in proper ascending order — comparing `nums[low]` to `nums[mid]` tells you which one. Once you know which half is sorted, a single range check (`nums[low] <= target < nums[mid]`, or the mirrored check for the right half) tells you whether the target could be in that sorted half or must be in the other one. This lets **binary search** still discard half the search space each step, just with an extra branch to figure out which half to trust, bringing the time down from `O(n)` to `O(log n)`.

## 6. Code it

```ts
function search(nums: number[], target: number): number {
  let low = 0;
  let high = nums.length - 1;

  while (low <= high) {
    const mid = low + Math.floor((high - low) / 2);

    if (nums[mid] === target) return mid;

    if (nums[low] <= nums[mid]) {
      if (nums[low] <= target && target < nums[mid]) {
        high = mid - 1;
      } else {
        low = mid + 1;
      }
    } else {
      if (nums[mid] < target && target <= nums[high]) {
        low = mid + 1;
      } else {
        high = mid - 1;
      }
    }
  }

  return -1;
}
```

## 7. Test it manually

- `nums = [4,5,6,7,0,1,2], target = 0` → traced in step 3 → `4` ✓
- `nums = [4,5,6,7,0,1,2], target = 3` → binary search narrows through both halves, never finds `3` → `low` crosses `high` → returns `-1` ✓
- `nums = [1], target = 0` → `low=0,high=0`; `mid=0`, `nums[0]=1 !== 0`; left half trivially sorted (`nums[low]<=nums[mid]`), `target=0` not in `[1,1)` → `low = mid+1 = 1` → loop ends (`low > high`) → returns `-1` ✓
- `nums = [5,1,3], target = 5` → `low=0,high=2`; `mid=1`, `nums[1]=1 !== 5`; `nums[low]=5 > nums[mid]=1` → right half `[1,3]` sorted; `target=5` not in `(1,3]` → `high = mid-1 = 0` → `low=0,high=0`; `mid=0`, `nums[0]=5 === target` → returns `0` ✓
- `nums = [1,2,3,4,5], target = 4` (no rotation) → ordinary binary search narrows straight to index `3` ✓

## 8. Review and log

- **Approach used:** modified binary search — at each step, determine which half of `[low, high]` is internally sorted by comparing `nums[low]` to `nums[mid]`, then use a range check against that sorted half to decide which side to keep searching.
- **Mistake to watch for:** getting the range check boundaries wrong (`<=` vs `<`) when deciding if `target` falls inside the sorted half — since values are distinct, the sorted half's bounds are inclusive on the side touching `low`/`high` and exclusive on the side touching `mid` (already checked for equality), so mixing these up causes off-by-one misses.
- **Recurring pattern to log:** "binary search with a local sortedness check" generalizes to any problem on a partially-disordered but piecewise-sorted structure — rotated arrays, finding a rotation's minimum, or searching in arrays with one discontinuity.

## Complexity

- **Time:** `O(log n)` — binary search halves the candidate range each iteration, regardless of the rotation point.
- **Space:** `O(1)` — a fixed number of pointer variables, no extra structures.
