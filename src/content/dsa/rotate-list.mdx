## 1. Restate the problem

Given the `head` of a linked list and an integer `k`, rotate the list to the right by `k` places — each rotation moves the last node to the front, shifting everything else one position to the right.

## 2. Inputs, outputs, edge cases

- **Input:** `head`, the head node of a singly linked list, with the number of nodes in `[0, 500]`; an integer `k`, `0 <= k <= 2 * 10^9`.
- **Output:** the head of the rotated list.
- **Constraints noted:**
  - `k` can be **far larger than the list's length** — e.g. a 3-node list with `k = 2000000000`. Naively rotating one step at a time `k` times would be catastrophically slow.
  - Rotating by exactly the list's length (or any multiple of it) returns the **same list unchanged** — a full rotation is a no-op.
  - `k = 0` → no rotation, list unchanged.
  - Empty list, or single-node list → nothing meaningful to rotate → return as-is regardless of `k`.
  - `k` not a multiple of the length → the effective rotation is `k % length`, some amount strictly between `0` and `length`.

## 3. Work a small example by hand — the `k % length` trick

`head = 1 -> 2 -> 3 -> 4 -> 5 -> null`, `k = 7`

The list has length `5`. Rotating by `5` places (a full loop) returns the exact same list — every node ends up back where it started. So rotating by `7` places has the *identical effect* as rotating by `7 % 5 = 2` places: the first `5` of those `7` rotations cancel out completely, leaving only `2` "real" rotations worth doing.

```
7 rotations = 1 full loop (5, no-op) + 2 effective rotations
7 % 5 = 2  →  effectiveK = 2
```

**Step 1 — find the length and close the list into a ring:** walk to the tail, recording length `= 5`, then link `tail.next = head` to form a circle: `1 -> 2 -> 3 -> 4 -> 5 -> (back to 1)`.

**Step 2 — compute the effective rotation:** `effectiveK = k % length = 7 % 5 = 2`.

**Step 3 — find the new tail and cut the ring:** the new tail sits at position `length - effectiveK - 1 = 5 - 2 - 1 = 2` (`0`-indexed) from the original head — that's node `3`. Walk `2` steps from `head` to reach it:

```
head(0)=1 -> (1)=2 -> (2)=3 -> (3)=4 -> (4)=5 -> back to 1
                        ^ new tail (index 2)
```

The node right after the new tail (`3.next`, which is `4`) becomes the **new head**. Cut the ring there: `3.next = null`.

Result: `4 -> 5 -> 1 -> 2 -> 3 -> null`, matching what 2 right-rotations of the original list would produce.

## 4. Brute force first

Rotate one step at a time, `k` times: each rotation moves the last node to the front.

```ts
class ListNode {
  val: number;
  next: ListNode | null = null;
  constructor(val: number) {
    this.val = val;
  }
}

function rotateRightBruteForce(head: ListNode | null, k: number): ListNode | null {
  if (head === null) return null;

  for (let i = 0; i < k; i++) {
    let curr = head;
    while (curr.next!.next !== null) {
      curr = curr.next!;
    }
    const last = curr.next!;
    curr.next = null;
    last.next = head;
    head = last;
  }

  return head;
}
```

- **Time:** `O(k * n)` — each of the `k` rotations walks the list to find its tail. With `k` up to `2 * 10^9`, this is completely infeasible.
- **Space:** `O(1)`, no extra structures — the space complexity is fine, but the time complexity makes this unusable for large `k`.

## 5. Identify the pattern and optimize

The key realization: rotating a list of length `n` by exactly `n` places returns it to its original state — a full rotation is a no-op. So any `k` can be reduced to an **effective rotation** of `k % length`, collapsing however many full loops `k` contains down to at most `length - 1` real rotations needed. Combined with the **close-the-ring-then-cut** technique — link the tail back to the head to form a circle, walk to the new cut point, then break the ring there — the whole rotation becomes a single `O(n)` pass to find the length, plus one more `O(n)` walk to the cut point, regardless of how astronomically large `k` is. This is what makes the algorithm robust against `k` values far exceeding the list's size.

## 6. Code it

```ts
function rotateRight(head: ListNode | null, k: number): ListNode | null {
  if (head === null || head.next === null || k === 0) return head;

  // find length and the tail
  let length = 1;
  let tail = head;
  while (tail.next !== null) {
    tail = tail.next;
    length++;
  }

  const effectiveK = k % length;
  if (effectiveK === 0) return head; // full rotation(s) only, no change

  // close into a ring
  tail.next = head;

  // walk to the new tail, just before the new head
  let stepsToNewTail = length - effectiveK - 1;
  let newTail = head;
  while (stepsToNewTail > 0) {
    newTail = newTail.next!;
    stepsToNewTail--;
  }

  const newHead = newTail.next!;
  newTail.next = null; // cut the ring

  return newHead;
}
```

## 7. Test it manually

- `1->2->3->4->5, k=7` → traced in step 3 → `4->5->1->2->3` ✓
- `head = [1,2], k = 4` → `length = 2`, `effectiveK = 4 % 2 = 0` → returns `head` unchanged (`1->2`) — a full-rotation multiple is correctly a no-op ✓
- `head = null, k = 5` → guard clause (`head === null`) → returns `null` ✓
- `head = [1], k = 1000000` → guard clause (`head.next === null`) → returns `[1]` unchanged (single node can't meaningfully rotate) ✓
- `head = [1,2,3], k = 0` → guard clause (`k === 0`) → returns `head` unchanged ✓
- `head = [0,1,2], k = 4` → `length=3`, `effectiveK = 4 % 3 = 1`; ring closed; `stepsToNewTail = 3-1-1=1` → walk 1 step from head to node `1` (the new tail); `newHead = 1.next = 2`; cut → result `2->0->1` ✓

## 8. Review and log

- **Approach used:** `k % length` to collapse an arbitrarily large `k` down to an effective rotation strictly less than the list's length, then close the list into a ring and cut it at the computed new head position.
- **Mistake to watch for:** computing `effectiveK` **before** checking it's `0` and skipping early is important — without that check, `length - effectiveK - 1` when `effectiveK = 0` computes `length - 1` (the last node), which would incorrectly cut the ring right before the original head instead of leaving the list untouched.
- **Recurring pattern to log:** "reduce a huge repeat count with `%` against a cycle length" generalizes to any problem involving repeated rotation, shifting, or stepping through a structure that wraps around (circular buffers, modular array rotation, clock-arithmetic problems).

## Complexity

- **Time:** `O(n)` — one pass to find the length, one more (partial) pass to reach the new cut point.
- **Space:** `O(1)` — a fixed number of pointer and counter variables, no extra structures.
