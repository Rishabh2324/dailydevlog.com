## 1. Restate the problem

You have `n` versions `[1, 2, ..., n]` and a version gets flagged "bad" if it's also bad in all the versions after it. You're given an API `isBadVersion(version)` that returns `true`/`false`. Find the **first** bad version, calling the API as few times as possible.

## 2. Inputs, outputs, edge cases

- **Input:** `n`, an integer `1 <= n <= 2^31 - 1`; access to `isBadVersion(version): boolean`.
- **Output:** the integer version number of the first bad version.
- **Constraints noted:**
  - There is guaranteed to be at least one bad version (`isBadVersion(n)` is always `true` per the problem setup).
  - The "bad" property is **monotonic**: once a version is bad, every later version is also bad. So the sequence looks like `good, good, ..., good, bad, bad, ..., bad`.
  - Must minimize API calls — a linear scan from `1` to `n` would work but wastes calls; the problem explicitly wants the minimal-call solution.
  - `n = 1` → that single version must be the bad one.

## 3. Work a small example by hand

`n = 5`, and suppose the hidden bad-version sequence is `[false, false, false, true, true]` (versions `4` and `5` are bad).

| low | high | mid | isBadVersion(mid) | action |
|-----|------|-----|--------------------|--------|
| 1 | 5 | 3 | false | not bad, search right: `low = 4` |
| 4 | 5 | 4 | true | bad, candidate = 4, search left: `high = 3` |

Loop ends (`low > high`). First bad version: `4` ✓.

## 4. Brute force first

Check versions one at a time starting from `1` until the first bad one is found.

```ts
function firstBadVersionBruteForce(n: number, isBadVersion: (v: number) => boolean): number {
  for (let v = 1; v <= n; v++) {
    if (isBadVersion(v)) return v;
  }
  return n;
}
```

- **Time:** `O(n)` API calls in the worst case — for `n` up to `2^31 - 1`, this is far too slow.
- **Space:** `O(1)`.

## 5. Identify the pattern and optimize

The sequence of `isBadVersion` results is monotonic — all `false` then all `true` — which is exactly the shape binary search needs. Instead of checking every version, binary search the range `[1, n]`: whenever `isBadVersion(mid)` is `true`, the first bad version is at `mid` or somewhere to its left, so keep `mid` as the current best candidate and search left; whenever it's `false`, the first bad version must be strictly to the right. This drops the number of API calls from `O(n)` to `O(log n)`.

## 6. Code it

```ts
function firstBadVersion(n: number, isBadVersion: (v: number) => boolean): number {
  let low = 1;
  let high = n;

  while (low < high) {
    const mid = low + Math.floor((high - low) / 2);

    if (isBadVersion(mid)) {
      high = mid;
    } else {
      low = mid + 1;
    }
  }

  return low;
}
```

## 7. Test it manually

- `n = 5`, bad from `4` onward → traced in step 3 → `4` ✓
- `n = 1`, bad from `1` onward → `low=1,high=1` → loop doesn't run (`low < high` false) → returns `1` ✓
- `n = 3`, bad from `1` onward (`[true,true,true]`) → `low=1,high=3`; `mid=2`, bad → `high=2`; `low=1,high=2`; `mid=1`, bad → `high=1`; loop ends → returns `1` ✓
- `n = 4`, bad only at `4` (`[false,false,false,true]`) → `low=1,high=4`; `mid=2`, not bad → `low=3`; `low=3,high=4`; `mid=3`, not bad → `low=4`; loop ends → returns `4` ✓

## 8. Review and log

- **Approach used:** binary search using `low < high` (not `<=`) with `high = mid` on a hit, converging `low` and `high` onto the exact boundary instead of tracking a separate "best answer so far" variable.
- **Mistake to watch for:** using `high = mid - 1` on a bad result (as in a typical "find exact match" binary search) would skip past the true answer if `mid` itself is the first bad version — since `mid` is still a valid candidate, it must stay in bounds (`high = mid`, not `mid - 1`).
- **Recurring pattern to log:** "binary search for a boundary between two monotonic regions" generalizes to any problem framed as finding where a condition flips from false to true exactly once (e.g. finding the transition point in a monotonic predicate, capacity/threshold search problems).

## Complexity

- **Time:** `O(log n)` — binary search halves the candidate range each call.
- **Space:** `O(1)` — a fixed number of pointer variables.
