## 1. Restate the problem

Given an array `nums` sorted in non-decreasing order and a `target` value, find the starting and ending index of `target` in `nums`. Return `[-1, -1]` if `target` is not found.

## 2. Inputs, outputs, edge cases

- **Input:** `nums`, an array of `0 <= nums.length <= 10^5` integers sorted in non-decreasing order (duplicates allowed); `target`, an integer.
- **Output:** a two-element array `[firstIndex, lastIndex]`, or `[-1, -1]` if `target` isn't present.
- **Constraints noted:**
  - Must run in `O(log n)` — a linear scan is not the intended solution.
  - Duplicates are explicitly allowed and expected — the whole point is finding the range of repeated values.
  - Empty array (`nums.length === 0`) → `[-1, -1]`.
  - `target` present exactly once → first and last index are the same.
  - `target` not present at all → `[-1, -1]`.
  - `target` could span the entire array (all elements equal to `target`).

## 3. Work a small example by hand

`nums = [5,7,7,8,8,10]`, `target = 8`

**Finding the first occurrence** (bias left: on a match, keep searching left for an earlier one):

| low | high | mid | nums[mid] | action |
|-----|------|-----|-----------|--------|
| 0 | 5 | 2 | 7 | `7 < 8` → `low = 3` |
| 3 | 5 | 4 | 8 | match → record `4`, keep searching left: `high = 3` |
| 3 | 3 | 3 | 8 | match → record `3`, keep searching left: `high = 2` |

Loop ends (`low=3 > high=2`). First index: `3`.

**Finding the last occurrence** (bias right: on a match, keep searching right for a later one):

| low | high | mid | nums[mid] | action |
|-----|------|-----|-----------|--------|
| 0 | 5 | 2 | 7 | `7 < 8` → `low = 3` |
| 3 | 5 | 4 | 8 | match → record `4`, keep searching right: `low = 5` |
| 5 | 5 | 5 | 10 | `10 > 8` → `high = 4` |

Loop ends (`low=5 > high=4`). Last index: `4`.

Result: `[3, 4]` ✓.

## 4. Brute force first

Scan linearly, tracking the first and last index where `nums[i] === target`.

```ts
function searchRangeBruteForce(nums: number[], target: number): number[] {
  let first = -1;
  let last = -1;
  for (let i = 0; i < nums.length; i++) {
    if (nums[i] === target) {
      if (first === -1) first = i;
      last = i;
    }
  }
  return [first, last];
}
```

- **Time:** `O(n)` — scans the whole array, violating the `O(log n)` requirement.
- **Space:** `O(1)`.

## 5. Identify the pattern and optimize

Since `nums` is sorted, all occurrences of `target` form one contiguous block. Finding the two boundaries of that block is two independent binary searches, each biased toward one edge: a **left-biased** search that, on every match, records the index and keeps narrowing `high = mid - 1` (always looking for an even earlier match), and a **right-biased** search that, on every match, records the index and keeps narrowing `low = mid + 1` (always looking for a later match). Each search is a standard `O(log n)` binary search; running both gives the full range in `O(log n)` total instead of the `O(n)` linear scan.

## 6. Code it

```ts
function searchRange(nums: number[], target: number): number[] {
  const findBound = (biasLeft: boolean): number => {
    let low = 0;
    let high = nums.length - 1;
    let result = -1;

    while (low <= high) {
      const mid = low + Math.floor((high - low) / 2);

      if (nums[mid] === target) {
        result = mid;
        if (biasLeft) {
          high = mid - 1;
        } else {
          low = mid + 1;
        }
      } else if (nums[mid] < target) {
        low = mid + 1;
      } else {
        high = mid - 1;
      }
    }

    return result;
  };

  return [findBound(true), findBound(false)];
}
```

## 7. Test it manually

- `nums = [5,7,7,8,8,10], target = 8` → traced in step 3 → `[3, 4]` ✓
- `nums = [5,7,7,8,8,10], target = 6` → both searches never find a match (`low` crosses `high` without setting `result`) → `[-1, -1]` ✓
- `nums = [], target = 0` → `low=0, high=-1` → loop never runs in either search → `[-1, -1]` ✓
- `nums = [2,2,2], target = 2` → left-biased search narrows down to index `0`; right-biased search narrows up to index `2` → `[0, 2]` ✓
- `nums = [1], target = 1` → both searches immediately find `mid=0` a match, narrow past bounds → `[0, 0]` ✓

## 8. Review and log

- **Approach used:** two boundary-seeking binary searches — one biased to keep shrinking toward the left on a match, one biased to keep shrinking toward the right — each still `O(log n)`.
- **Mistake to watch for:** returning immediately on the first match found (like a standard "does target exist" binary search) gives *some* occurrence, not necessarily the first or last — the key fix is to **keep searching past a match** in the appropriate direction and only stop when the range is exhausted, recording the best boundary seen so far.
- **Recurring pattern to log:** "binary search for a boundary, not just existence" generalizes to any problem needing the first/last position satisfying a condition in a sorted or monotonic sequence — counting occurrences, range queries, or finding the edge of a contiguous block of values.

## Complexity

- **Time:** `O(log n)` — two independent binary searches, each halving the range per iteration.
- **Space:** `O(1)` — a fixed number of pointer variables, no extra structures.
