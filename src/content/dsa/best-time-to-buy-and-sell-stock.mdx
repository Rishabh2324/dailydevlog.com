## 1. Restate the problem

You're given an array `prices` where `prices[i]` is the price of a stock on day `i`. You want to choose a single day to buy the stock and a different, later day to sell it, in order to maximize profit. Return the maximum profit achievable. If no profit is possible, return `0`.

## 2. Inputs, outputs, edge cases

- **Input:** an array of integers `prices`, length `1 <= prices.length <= 10^5`, `0 <= prices[i] <= 10^4`.
- **Output:** an integer, the maximum profit from buying on one day and selling on a later day. `0` if no profitable transaction exists.
- **Constraints noted:**
  - Must buy before you sell — the sell day must come strictly after the buy day.
  - Only one transaction allowed (one buy, one sell) — not multiple trades.
  - Prices strictly decreasing throughout → no profitable transaction → return `0`.
  - Single-element array → no valid sell day → return `0`.
  - All prices equal → profit is `0`.

## 3. Work a small example by hand

`prices = [7, 1, 5, 3, 6, 4]`

Track the minimum price seen so far (`minPrice`) and the best profit found so far (`maxProfit`), scanning left to right:

| i | price | minPrice before | profit if sold today | maxProfit after | minPrice after |
|---|-------|------------------|-----------------------|------------------|-----------------|
| 0 | 7     | ∞                | -                     | 0                | 7               |
| 1 | 1     | 7                | -6                    | 0                | 1               |
| 2 | 5     | 1                | 4                     | 4                | 1               |
| 3 | 3     | 1                | 2                     | 4                | 1               |
| 4 | 6     | 1                | 5                     | 5                | 1               |
| 5 | 4     | 1                | 3                     | 5                | 1               |

Final `maxProfit = 5`, matching the expected output (buy at `1`, sell at `6`).

## 4. Brute force first

Try every pair of buy/sell days and keep the best profit.

```ts
function maxProfitBruteForce(prices: number[]): number {
  let maxProfit = 0;

  for (let i = 0; i < prices.length; i++) {
    for (let j = i + 1; j < prices.length; j++) {
      const profit = prices[j] - prices[i];
      if (profit > maxProfit) {
        maxProfit = profit;
      }
    }
  }

  return maxProfit;
}
```

- **Time:** `O(n^2)` for the nested pair comparisons.
- **Space:** `O(1)`, no extra structures used.

## 5. Identify the pattern and optimize

This is a **single-pass greedy tracking** problem: the only thing that matters for a given sell day is the lowest price seen at any point *before* it, since buying at the lowest prior price always maximizes profit for that sell day. Instead of comparing every pair, scan once while maintaining a running minimum (`minPrice`) and updating a running best (`maxProfit = max(maxProfit, price - minPrice)`) at each day. This collapses the nested comparison into one pass, dropping `O(n^2)` down to `O(n)` time with `O(1)` space.

## 6. Code it

```ts
function maxProfit(prices: number[]): number {
  let minPrice = Infinity;
  let maxProfit = 0;

  for (const price of prices) {
    if (price < minPrice) {
      minPrice = price;
    } else if (price - minPrice > maxProfit) {
      maxProfit = price - minPrice;
    }
  }

  return maxProfit;
}
```

## 7. Test it manually

- `prices = [7, 1, 5, 3, 6, 4]` → traced in step 3 → `maxProfit = 5` ✓
- `prices = [7, 6, 4, 3, 1]` → strictly decreasing → `minPrice` keeps dropping, `price - minPrice` never positive → `maxProfit = 0` ✓
- `prices = [1]` → single element, loop only sets `minPrice = 1`, no second comparison ever happens → `maxProfit = 0` ✓
- `prices = [2, 2, 2]` → `minPrice = 2`, every `price - minPrice = 0` → `maxProfit = 0` ✓

## 8. Review and log

- **Approach used:** single-pass greedy tracking — maintain the minimum price seen so far and the best profit achievable by selling today against that minimum.
- **Mistake to watch for:** updating `minPrice` and checking the profit in the wrong order, or checking profit even when the current price *is* the new minimum, can miss the correct pairing or compute a same-day "sell before buy" profit — keep the `else if` so a new minimum doesn't also get treated as a sell day.
- **Recurring pattern to log:** "track a running best-so-far value while scanning once" generalizes to problems like maximum subarray sum, best time to buy/sell with cooldown, or any "best result ending at position i" single-pass tracking problem.

## Complexity

- **Time:** `O(n)` — one pass through the prices array.
- **Space:** `O(1)` — two running variables, no extra data structures.
