## 1. Restate the problem

Given a non-negative integer `x`, return the square root of `x` rounded **down** to the nearest integer (the floor of `sqrt(x)`). Built-in exponent/sqrt functions (like `pow(x, 0.5)`) are not allowed.

## 2. Inputs, outputs, edge cases

- **Input:** `x`, an integer with `0 <= x <= 2^31 - 1`.
- **Output:** an integer, `floor(sqrt(x))`.
- **Constraints noted:**
  - `x = 0` → `0`.
  - `x = 1` → `1`.
  - Perfect squares (`4`, `9`, `16`, ...) → the exact root.
  - Non-perfect squares (`8`, `10`, ...) → truncate down, not round to nearest (e.g. `sqrt(8) ≈ 2.828` → `2`, not `3`).
  - `x` can be as large as `2^31 - 1`, so intermediate values like `mid * mid` can overflow a 32-bit int in some languages — needs to be handled safely (not an issue in JS/TS numbers, but worth noting).

## 3. Work a small example by hand

`x = 8`

We're looking for the largest integer `m` such that `m * m <= 8`.

| low | high | mid | mid*mid | compare to 8 | action |
|-----|------|-----|---------|--------------|--------|
| 0 | 8 | 4 | 16 | 16 > 8 | too big, high = 3 |
| 0 | 3 | 1 | 1 | 1 <= 8 | candidate = 1, low = 2 |
| 2 | 3 | 2 | 4 | 4 <= 8 | candidate = 2, low = 3 |
| 3 | 3 | 3 | 9 | 9 > 8 | too big, high = 2 |

Loop ends (`low > high`). Best candidate found: `2`. `sqrt(8) ≈ 2.828`, floor is `2` ✓.

## 4. Brute force first

Count up from `0` until the next integer's square exceeds `x`.

```ts
function mySqrtBruteForce(x: number): number {
  let i = 0;
  while (i * i <= x) {
    i++;
  }
  return i - 1;
}
```

- **Time:** `O(sqrt(x))` — walks every integer from `0` up to the answer. For `x` near `2^31`, that's roughly `46000` iterations — works, but far more than necessary.
- **Space:** `O(1)`.

## 5. Identify the pattern and optimize

The set of candidate integers `0..x` is monotonic with respect to the test "is `m * m <= x`?" — once `m * m` exceeds `x`, every larger `m` also fails, and every smaller `m` still passes. That monotonic yes/no boundary is exactly what **binary search** is built for: instead of walking up one integer at a time, repeatedly test the midpoint of a shrinking `[low, high]` range, keep the largest `mid` seen whose square doesn't exceed `x`, and discard half the remaining candidates each time. This drops the search from `O(sqrt(x))` down to `O(log x)`.

## 6. Code it

```ts
function mySqrt(x: number): number {
  if (x < 2) return x;

  let low = 1;
  let high = x;
  let answer = 1;

  while (low <= high) {
    const mid = low + Math.floor((high - low) / 2);
    const square = mid * mid;

    if (square === x) {
      return mid;
    } else if (square < x) {
      answer = mid;
      low = mid + 1;
    } else {
      high = mid - 1;
    }
  }

  return answer;
}
```

## 7. Test it manually

- `x = 8` → traced in step 3 → `2` ✓
- `x = 4` → `low=1,high=4`; `mid=2`, `4===4` → returns `2` immediately ✓
- `x = 0` → guard clause (`x < 2`) → returns `0` ✓
- `x = 1` → guard clause (`x < 2`) → returns `1` ✓
- `x = 2147395599` (large non-perfect square near the upper bound) → binary search converges in ~31 steps instead of ~46000 → returns `46339` (`46339^2 = 2147298721 <= x`, `46340^2 = 2147395600 > x`) ✓

## 8. Review and log

- **Approach used:** binary search over the answer space `[1, x]`, using the monotonic property of `m * m <= x` to discard half the candidates each iteration, tracking the best valid `mid` seen so far.
- **Mistake to watch for:** returning `mid` directly on loop exit is wrong — when the loop ends without hitting an exact match, `mid` may have just overshot past the true answer (`high` decremented below it). Track the last known-valid `mid` in a separate `answer` variable instead of relying on the final `low`/`high`/`mid` state.
- **Recurring pattern to log:** "binary search on the answer" — whenever a problem asks for the largest/smallest value satisfying some monotonic predicate (`f(m)` flips from true to false exactly once as `m` increases), binary search directly over the candidate values instead of testing every one. This generalizes to problems like finding minimum capacity, splitting arrays under a max-sum constraint, or koko-eating-bananas style optimization.

## Complexity

- **Time:** `O(log n)` — binary search halves the candidate range each iteration.
- **Space:** `O(1)` — a fixed number of pointer variables, no extra structures.
