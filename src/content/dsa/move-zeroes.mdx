## 1. Restate the problem

Given an integer array `nums`, move all `0`s to the end of it while maintaining the relative order of the non-zero elements. This must be done **in place**, without making a copy of the array.

## 2. Inputs, outputs, edge cases

- **Input:** an array of integers `nums`, length `1 <= nums.length <= 10^4`.
- **Output:** none returned — `nums` is modified in place so all zeroes sit at the end, non-zero elements keep their original relative order at the front.
- **Constraints noted:**
  - Relative order of non-zero elements **must** be preserved — unlike "remove element," order matters here.
  - In-place modification only — no extra array for the result.
  - Array length `< 2` (single element) → nothing to move, return as-is.
  - No zeroes at all → array unchanged.
  - All zeroes → array unchanged (already "moved" to the end).
  - Zeroes scattered anywhere: start, middle, end, or consecutive runs.

## 3. Work a small example by hand

`nums = [0, 1, 0, 3, 12]`

**Pass 1** — track a write pointer `p1` (next slot for a non-zero value, starts at `0`), scan with `i` from `0`, and whenever `nums[i] !== 0`, copy it to `nums[p1]` and advance `p1`:

| i | nums[i] | is zero? | action           | p1 after |
|---|---------|----------|-------------------|----------|
| 0 | 0       | yes      | skip              | 0        |
| 1 | 1       | no       | nums[0]=1 → p1=1  | 1        |
| 2 | 0       | yes      | skip              | 1        |
| 3 | 3       | no       | nums[1]=3 → p1=2  | 2        |
| 4 | 12      | no       | nums[2]=12 → p1=3 | 3        |

After pass 1: `nums = [1, 3, 12, 3, 12]` (positions `0..2` are correct; positions `3..4` are stale leftovers), `p1 = 3`.

**Pass 2** — fill everything from `p1` to the end with `0`:

`nums[3] = 0`, `nums[4] = 0` → final `nums = [1, 3, 12, 0, 0]`, matching the expected output.

## 4. Brute force first

Filter out the zeroes into a new array, then rebuild `nums` by copying the non-zero values back followed by zero-padding.

```ts
function moveZeroesBruteForce(nums: number[]): void {
  const nonZero = nums.filter((n) => n !== 0);

  for (let i = 0; i < nums.length; i++) {
    nums[i] = i < nonZero.length ? nonZero[i] : 0;
  }
}
```

- **Time:** `O(n)` for the filter and the rebuild pass.
- **Space:** `O(n)` for the `nonZero` array — violates the in-place constraint (the extra array scales with input size).

## 5. Identify the pattern and optimize

This is a **two-pointer, two-pass** in-place array problem, closely related to "remove element" and "remove duplicates from sorted array." The first pass uses a write pointer `p1` to compact every non-zero value to the front, in the order encountered — this alone produces the correct prefix but leaves stale duplicate values trailing behind it (since values are overwritten, not swapped). The second pass then simply zeroes out everything from `p1` onward, cleaning up those leftovers. Because both passes are linear scans over the same array with only index variables as state, this achieves `O(n)` time and `O(1)` space with no auxiliary array.

## 6. Code it

```ts
function moveZeroes(nums: number[]): void {
  if (nums.length < 2) return;

  let p1 = 0;

  for (let i = 0; i < nums.length; i++) {
    if (nums[i] !== 0) {
      nums[p1] = nums[i];
      p1++;
    }
  }

  for (let i = p1; i < nums.length; i++) {
    nums[i] = 0;
  }
}
```

## 7. Test it manually

- `nums = [0, 1, 0, 3, 12]` → traced in step 3 → `[1, 3, 12, 0, 0]` ✓
- `nums = [0]` → `nums.length < 2` → returns immediately, `nums` stays `[0]` ✓
- `nums = [1, 2, 3]` → no zeroes, every element copied to itself, `p1` ends at `3`, second loop does nothing → `[1, 2, 3]` unchanged ✓
- `nums = [0, 0, 0]` → first loop never advances `p1` (stays `0`), second loop zeroes indices `0..2` (already zero) → `[0, 0, 0]` ✓

## 8. Review and log

- **Approach used:** two-pointer, two-pass compaction — a write pointer `p1` first pulls all non-zero values forward in order, then a cleanup pass zeroes out everything left behind.
- **Mistake to watch for:** this problem requires preserving relative order, so a naive single-pass "swap zero with next non-zero" needs care with pointer movement; the two-pass write-then-zero approach sidesteps that entirely by not caring what garbage is left behind until the second pass overwrites it.
- **Recurring pattern to log:** "write pointer compacts values worth keeping, followed by a cleanup pass for the tail" generalizes the "remove element" write-pointer pattern to problems where the removed/displaced values still need an explicit resting place (here, `0`) rather than simply being discarded.

## Complexity

- **Time:** `O(n)` — two linear passes over the array (compaction, then zero-fill).
- **Space:** `O(1)` — modifies the array in place with two index variables.
