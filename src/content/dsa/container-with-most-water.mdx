## 1. Restate the problem

Given an integer array `height` where `height[i]` is the height of a vertical line drawn at `x = i`, find two lines that, together with the x-axis, form a container that holds the most water. Return the maximum amount of water the container can store. Note that the container cannot be slanted — the amount of water it holds is bounded by the shorter of the two lines.

## 2. Inputs, outputs, edge cases

- **Input:** `height` — an array of non-negative integers with `n == height.length`, `2 <= n <= 10^5`, `0 <= height[i] <= 10^4`.
- **Output:** a single integer — the maximum water area achievable.
- **Constraints noted:**
  - Exactly two lines form the container; area = `min(height[left], height[right]) * (right - left)`.
  - All heights could be equal (area is then purely a function of index distance).
  - The tallest lines might be adjacent (small width) or at the very ends (max width) — the optimum isn't always "pick the two tallest."
  - A height of `0` at either end still counts as a valid line (area with it will always be `0` if paired against it as the limiting side).

## 3. Work a small example by hand

## 4. Brute force first

Try every pair `(i, j)` and compute the area, keeping the maximum.

```ts
function maxAreaBruteForce(height: number[]): number {
  let best = 0;

  for (let i = 0; i < height.length; i++) {
    for (let j = i + 1; j < height.length; j++) {
      const area = Math.min(height[i], height[j]) * (j - i);
      best = Math.max(best, area);
    }
  }

  return best;
}
```

- **Time:** `O(n^2)` — every pair of indices is checked.
- **Space:** `O(1)`.

## 5. Identify the pattern and optimize

This is a **two-pointer greedy** problem. Start with the widest possible container: `left = 0`, `right = n - 1`. At each step the width can only shrink as the pointers move inward, so the only way a narrower container beats the current best is if it has a taller limiting side. The limiting side is always the shorter of the two — moving the *taller* pointer inward can only keep the same limiting height (or make it worse, since the other side is still the min) while strictly reducing width, so it can never improve the area. Moving the *shorter* pointer inward is the only move that has a chance of increasing the limiting height enough to compensate for the lost width. So the greedy rule is: always discard the shorter line and move that pointer inward, recording the area at every step. Since each step moves one pointer and the pointers meet after at most `n` steps, this collapses `O(n^2)` pair-checking into a single `O(n)` pass.

## 6. Code it

```ts
function maxArea(height: number[]): number {
  let left = 0;
  let right = height.length - 1;
  let best = 0;

  while (left < right) {
    const width = right - left;
    const limitingHeight = Math.min(height[left], height[right]);
    best = Math.max(best, limitingHeight * width);

    if (height[left] < height[right]) {
      left++;
    } else {
      right--;
    }
  }

  return best;
}
```

## 7. Test it manually

- `height = [1,8,6,2,5,4,8,3,7]` → traced by hand above, pointers converge with a running max of `49` → return `49` ✓ (matches LeetCode's expected output).
- `height = [1,1]` → `left=0, right=1`, width `1`, limiting height `1`, area `1`; `height[left] == height[right]` so `right--`, loop ends → return `1` ✓.
- `height = [4,3,2,1,4]` → `left=0(4), right=4(4)`, area `min(4,4)*4 = 16`; equal heights so move `right--` to `3(1)`, area `min(4,1)*3=3`; continue shrinking from the right since `height[right] < height[left]` until pointers meet — best stays `16` → return `16` ✓.
- `height = [1,2,1]` → `left=0(1), right=2(1)`, area `1*2=2`; equal so `right--` to `1(2)`, loop ends (`left==right` next) → return `2` ✓.

## 8. Review and log

- **Approach used:** two-pointer greedy starting from the widest container, always discarding the shorter line since it's the bottleneck and can only get worse (never better) at a narrower width.
- **Mistake to watch for:** moving the *taller* pointer instead of the shorter one — that's mathematically guaranteed to never improve the area, so it wastes the whole point of the greedy proof and can make the algorithm return a suboptimal answer if implemented backward.
- **Recurring pattern to log:** "shrink from both ends, always move the pointer bounded by the worse constraint" is the same idea behind `trapping-rain-water` and other two-pointer problems where a local minimum determines a global bound.

## Complexity

- **Brute force — Time:** `O(n^2)`, **Space:** `O(1)`.
- **Two pointer — Time:** `O(n)` — each pointer moves at most `n` times total. **Space:** `O(1)`.
