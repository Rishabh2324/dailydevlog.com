## Why this matters

Gradient descent needs to know how to change every weight. A large model has billions of weights. Backpropagation
is the trick that works out all those changes quickly. Without it, deep learning wouldn't be practical.

By the end of this lesson, you'll be able to explain backpropagation as "passing the blame backwards".

## The idea

When a network gives a wrong answer, **backpropagation** figures out **how much each weight was to blame**.

It starts at the output, where the error is known. Then it moves backwards through the layers. At each layer it
asks: "how much did this weight push the answer in the wrong direction?" That share of blame is the weight's
gradient. Gradient descent then adjusts each weight based on it.

```text
forward pass:   input → layer 1 → layer 2 → output → loss
backward pass:  input ← layer 1 ← layer 2 ← output ← loss
                (blame flows back to every weight)
```

## A real-life example

Think of a **restaurant kitchen** where a customer sends back a dish because it's too salty.

The head chef doesn't blame everyone equally. They trace it backwards: the plate came from the sauce station; the
sauce used stock from the prep cook; the stock had too much salt added. Each person gets feedback in proportion to
how much they caused the problem. The sauce cook adjusts a bit, the prep cook adjusts more.

Backpropagation does the same for weights. The ones that caused most of the error change the most.

## How it works

1. **Forward pass.** The input goes through the network, layer by layer, and produces an answer.
2. **Compute the loss.** Compare the answer with the correct one (lesson 1.1.6).
3. **Backward pass.** Start at the output. Work out how the loss changes if each output-layer weight changes a
   little. Then use those results to do the same for the layer before, and so on, back to the first layer.
4. **Reuse work.** Each layer reuses what the layer after it already calculated. That's why it's fast: one backward
   pass costs roughly as much as a couple of forward passes, not billions of separate checks.
5. **Update.** Gradient descent uses the gradients to change every weight a little (lesson 1.1.7).

The math behind step 3 is the **chain rule** from calculus. You don't need it to use AI tools. Libraries such as
**PyTorch** do it automatically; this is called **autograd** (automatic differentiation).

The method was known earlier, but a 1986 paper by Rumelhart, Hinton and Williams made it the standard way to train
neural networks.

## Where you'll see it

- **Training vs inference cost:** training needs a forward and a backward pass, so it takes more compute and memory
  than just using a model (lesson 1.1.9).
- **"Frozen" layers in fine-tuning:** some layers skip weight updates, which saves memory (lesson 8.2.2).
- **Deep learning libraries** (PyTorch, JAX, TensorFlow) all have autograd built in.
- **History of AI:** backpropagation plus GPUs plus lots of data is why deep learning took off around 2012.

## Common confusions

- **Backpropagation is not a learning algorithm by itself.** It only computes gradients. Gradient descent does the
  updating.
- **The model doesn't backpropagate while you chat with it.** Using a model is a forward pass only. Weights change
  only during training.
- **You never do it by hand in practice.** Understanding the idea is enough; the library handles it.

## Key terms

| Term | Meaning |
|---|---|
| Forward pass | Running input through the network to get an answer |
| Backward pass | Passing the error back through the network to get gradients |
| Backpropagation | The method that computes every weight's gradient efficiently |
| Chain rule | The calculus rule backpropagation is built on |
| Autograd | Library feature that computes gradients automatically |
