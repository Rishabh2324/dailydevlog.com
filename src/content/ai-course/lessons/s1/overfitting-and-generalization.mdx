## Why this matters

A model that scores 99% in testing can still fail badly with real users. The usual reason is overfitting. It's the
most common way machine learning goes wrong, and it also explains why AI benchmarks can be misleading.

By the end of this lesson, you'll know what overfitting is, how people detect it, and why "test data" must stay
separate.

## The idea

**Generalization** means a model does well on new data it has never seen. That's the whole goal.

**Overfitting** means the model learned the training examples too exactly, including their noise and quirks. It
memorized instead of understanding. It looks perfect on training data and does worse on anything new.

**Underfitting** is the opposite: the model is too simple to learn even the training data well.

```text
underfitting        good fit            overfitting
too simple          learns the pattern  memorizes every point
bad everywhere      good on new data    great on training only
```

## A real-life example

Think of two students preparing for an exam.

- **Student A memorizes the answers to last year's paper.** If the same questions come up, they score 100%. If the
  questions change even a little, they fail.
- **Student B learns the concepts behind the questions.** They may score a bit lower on last year's paper, but they
  handle new questions well.

Student A overfit. Student B generalized. A model trained too long on too few examples becomes Student A.

This also happens with AI benchmarks. If a model's training data accidentally included a benchmark's test
questions, its score looks great without real skill. This is called **benchmark contamination**, and it's why
people are careful when reading leaderboards (lesson 6.1.2).

## How it works

1. **Split your data** into three parts:
   - a **training set** the model learns from,
   - a **validation set** you use to compare settings and decide when to stop,
   - a **test set** you use once, at the very end, to estimate real-world performance.
2. **Watch both losses.** If training loss keeps falling but validation loss starts rising, the model has begun to
   overfit.
3. **Use the usual fixes:**
   - more (and more varied) training data,
   - a simpler or smaller model,
   - stopping training earlier (**early stopping**),
   - **regularization**: techniques that discourage the model from memorizing, such as penalizing very large weights.
4. **Keep the test set clean.** If test data leaks into training, even by accident, your final score is fake. This
   is called **data leakage**.

## Where you'll see it

- **Training charts** with a training curve and a validation curve that drift apart.
- **Fine-tuning** a model on a small dataset: it can overfit in a few epochs and start repeating training examples.
- **Benchmarks and leaderboards**, where contamination can inflate scores.
- **Your own evals** for AI features (lesson 2.5.1): if you tune prompts on the same examples you test on, you
  overfit your prompt.

## Common confusions

- **High training accuracy isn't success.** Only performance on unseen data tells you if the model works.
- **Validation set vs test set:** you look at the validation set often; the test set only at the end. Looking at the
  test set repeatedly slowly turns it into another validation set.
- **Big models don't always overfit.** Very large neural networks trained on huge datasets often generalize well.
  Overfitting is mostly a risk when data is small compared with the model.

## Key terms

| Term | Meaning |
|---|---|
| Generalization | Doing well on new, unseen data |
| Overfitting | Memorizing training data and doing worse on new data |
| Underfitting | Being too simple to learn the pattern at all |
| Training / validation / test set | Data to learn from / to tune with / for the final check |
| Regularization | Techniques that discourage memorizing |
| Data leakage | Test information sneaking into training |
