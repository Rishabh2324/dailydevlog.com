## Why this matters

As a developer, you solve problems by writing rules: `if`, `else`, loops. Machine learning solves problems in a
different way. Knowing when each way fits is the most useful AI judgment a software engineer can have.

By the end of this lesson, you'll know what a "learned function" is and when learning beats writing rules.

## The idea

In **normal programming**, you write the rules. The computer applies them to data and gives answers.

In **machine learning**, you give the computer data and the correct answers. It figures out the rules by itself.
The result is a **learned function**: a function nobody wrote line by line. It was shaped by examples.

```text
Normal programming:   rules + data     →  answers
Machine learning:     data + answers   →  rules
```

This way of drawing the difference comes from François Chollet (*Deep Learning with Python*).

## A real-life example

Think about how a child learns what a dog is.

Nobody gives the child a rulebook: "four legs, fur, tail, barks". That rulebook would fail anyway. Some dogs have no
tail, cats also have four legs, and a toy dog doesn't bark. Instead, the child sees many dogs, a parent says "dog",
and the child learns the pattern. Soon they recognize a breed they have never seen.

Machine learning works the same way. **Gmail's spam filter** is a real case. Writing rules like "contains 'free
money'" breaks quickly, because spammers change words. So the filter learns from the huge number of emails people
mark as spam, and it keeps up as spam changes.

## How it works

1. **Collect examples.** For example, 10,000 emails, each labeled "spam" or "not spam".
2. **Pick a model.** A model is a function with many adjustable numbers inside it, called parameters (lesson 1.1.5).
3. **Train it.** The computer adjusts those numbers again and again until the model's answers match the labels as
   often as possible (lessons 1.1.6 and 1.1.7).
4. **Use it.** The trained model now works like a normal function: email in, "spam" or "not spam" out.
5. **Check it on new data.** A model can do well on the examples it saw and still fail on new ones (lesson 1.1.10).

The key shift: you stop writing the logic. You spend your effort on good examples and on checking results.

## Where you'll see it

- **Fuzzy problems** use learned functions: spam, fraud, face recognition, translation, recommendations.
- **Exact problems** still use rules: tax calculations, permissions, payments, form validation.
- **Most real products mix both.** A checkout uses rules for prices and a learned model for fraud risk.
- **LLMs are learned functions too**, just very large ones. Nobody wrote the rules for how ChatGPT answers.

## Common confusions

- **Machine learning isn't always better.** If you can write the rules clearly, rules are cheaper, faster and
  easier to explain. Google's own ML guide says you can launch without machine learning first (Zinkevich).
- **A learned function isn't magic.** It only knows patterns from its examples. Bad or biased examples give bad
  results.
- **"Learning" happens during training, not while you use it.** A spam filter doesn't change with each email unless
  it is retrained (lesson 1.1.9).

## Key terms

| Term | Meaning |
|---|---|
| Rule-based system | Software where people write the logic by hand |
| Learned function | A function whose behavior comes from training on examples |
| Model | The learned function, with its adjustable numbers inside |
| Training data | The examples, often with correct answers, used to train a model |
| Label | The correct answer attached to a training example |
