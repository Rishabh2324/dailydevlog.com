## Why this matters

Model names often include a number: Llama 3 **8B**, Qwen **72B**, "a **1 trillion** parameter model". That number
tells you a lot: roughly how capable the model is, how much memory it needs, and whether it can run on your laptop.

By the end of this lesson, you'll know what parameters, weights and biases are, and what "7B" means in practice.

## The idea

**Parameters** are the numbers inside a model that get adjusted during training. They are what the model "learned".
There are two main kinds:

- A **weight** says how much one input matters to a neuron. A big weight means "pay attention to this"; a weight
  near zero means "ignore this".
- A **bias** is a starting offset for a neuron. It shifts the result up or down, whatever the inputs are.

When training is finished, the model is basically a huge file full of these numbers.

## A real-life example

Think of a **mixing desk in a music studio**. It has many sliders: vocals, drums, bass, guitar. Each slider decides
how loud one input is in the final song. That's a weight. There's also a master volume knob that shifts everything
up or down. That's a bias.

A sound engineer moves the sliders until the song sounds right. Training does the same with a model's parameters,
automatically, until the answers are right.

Now imagine a mixing desk with **7 billion sliders**. That's a 7B model. Meta's Llama 2 7B, for example, has about
6.7 billion parameters (Touvron et al., 2023).

## How it works

1. **Every connection has a weight.** If a layer has 1,000 neurons and the next layer has 1,000, there are
   1,000 × 1,000 = 1 million weights between them.
2. **Every neuron has a bias.** That adds a much smaller number.
3. **Big models add up fast.** Many large layers quickly reach billions of parameters.
4. **Each parameter takes memory.** At 16-bit precision, each one needs 2 bytes. So a 7B model needs about 14 GB just
   to load, before doing any work (Hugging Face docs give this rule of thumb).
5. **Smaller number formats save memory.** Storing each parameter in 4 bits instead of 16 cuts that to about 3.5 GB.
   This is called **quantization** (lesson 8.1.3).

```text
7 billion parameters × 2 bytes (16-bit) ≈ 14 GB of memory
7 billion parameters × 0.5 bytes (4-bit) ≈ 3.5 GB of memory
```

## Where you'll see it

- **Model names and cards:** "7B", "70B", "405B" are parameter counts.
- **Running models locally:** a model that needs 14 GB won't fit on a laptop GPU with 8 GB, unless it is quantized.
- **Cost and speed:** more parameters usually mean slower and more expensive answers.
- **"Open weights" models** let you download these parameter files and run them yourself (lesson 8.1.1).

## Common confusions

- **More parameters doesn't always mean a better model.** A newer 8B model trained on more and better data can beat
  an older 70B model (lesson 1.1.13).
- **Parameters are not the training data.** The model doesn't store its training documents. It stores numbers that
  capture patterns from them.
- **Weights vs parameters:** people often say "weights" to mean all parameters, as in "download the model weights".

## Key terms

| Term | Meaning |
|---|---|
| Parameter | Any number inside a model that is learned during training |
| Weight | A parameter that sets how much one input matters |
| Bias | A parameter that shifts a neuron's output up or down |
| 7B, 70B | A model with about 7 or 70 billion parameters |
| Precision | How many bits store each number, like 16-bit or 4-bit |
