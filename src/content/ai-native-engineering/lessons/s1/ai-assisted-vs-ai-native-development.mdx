## Why this matters

You probably already use AI. It autocompletes lines, or you paste an error into a chat when you're stuck. But
the way you handle a ticket hasn't changed: you read it, you figure it out, you write the code, and AI helps now
and then.

By the end of this lesson, you'll be able to take one small ticket and let AI draft each step while you make the
decisions.

## How to do it

Here's the difference in one picture:

```text
AI-assisted  you plan → you code (AI helps) → you test → PR

AI-native    AI drafts questions + plan → you decide
             AI drafts code + tests     → you review
             AI drafts PR description   → you edit
```

The first is **AI-assisted**: you do the work, and AI helps when you ask. The second is **AI-native**: AI writes
the first draft of every step, and your job is to decide and check.

1. Pick a small ticket, something that takes a few hours. **(you decide)**
2. Give AI the ticket and the code it touches. Ask for open questions and a short plan. No code yet.
3. Answer the questions that change the code. Cut the plan down to what you really need. **(you decide)**
4. Ask AI to write the code and tests from your plan. Run the tests and read the whole diff. **(you decide if
   it's good)**
5. Ask AI to draft the PR description, then fix anything that's wrong.

Asking for a plan before any code is the order Anthropic recommends for its coding agent: explore, then plan, then
code (Anthropic, Claude Code best practices). It stops the AI from quickly building the wrong thing.

## Example

ShipLog is the team changelog app used in this course. The ticket and component are invented for this lesson. The
AI output is real: Claude Sonnet, 2026-09-17, trimmed.

```text
Ticket SHIP-155: "Add a 'Copy link' button to each entry
on the public changelog page."

[ChangelogEntry component pasted here: an <article
id={entry.slug}> with a title, date and body]

Don't write code yet.
1. List the questions I should answer before building this.
2. Give a short plan (max 5 steps), including the tests.
```

```md
## Questions to answer first

1. **What gets copied?** Full URL with `#slug` anchor (e.g. `https://site.com/changelog#entry-slug`), or something else (deep link vs. canonical page URL)?
[... question 2 trimmed ...]
3. **Feedback UX** — does clicking show a "Copied!" toast/tooltip, icon swap, or nothing? How long should confirmation last?
4. **Fallback for unsupported clipboard API** — do we need `document.execCommand` fallback for older browsers, or is `navigator.clipboard` support (HTTPS-only) acceptable?
[... questions 5–6 trimmed ...]
7. **Analytics** — does product want a tracking event on copy (existing analytics hook in this codebase)?

## Plan (max 5 steps)

[... steps 1–3 trimmed ...]
4. **Tests:**
   - Clicking calls `navigator.clipboard.writeText` with the expected URL containing `entry.slug` (mock `navigator.clipboard`).
   - Shows and then clears the "Copied" confirmation state after the click (timer-based, use fake timers).
   [... other tests trimmed ...]
5. Manual check in a browser: click the button on a real entry, confirm the pasted URL loads and scrolls to that entry via the `id={entry.slug}` anchor.
```

What the engineer did with it:

- Answered two questions in one line each: copy the full URL with `#slug`, and show "Copied" for 2 seconds.
- Dropped the old-browser fallback. `execCommand` is deprecated, and ShipLog only supports modern browsers.
- Sent the analytics question to the PM instead of guessing.
- Kept the test list. It became their checklist when they reviewed the code the AI wrote next.

Each of those questions was a choice. Without the plan step, the AI would have made them quietly, inside the code.

## Watch out

- Planning a ten-minute fix is slower than just doing it. Use this for tickets that take an hour or more.
- AI asks a lot of questions. Only answer the ones that change the code.
- Passing tests only prove that the AI's tests pass. You still read the diff.
- Don't paste work code into a tool your company hasn't approved.

## Try it

Take a small ticket from your real work, or use SHIP-155. Follow the five steps.

Done looks like: a PR where you can explain every line, and one thing from the AI's plan that you cut or changed.

<Answer label="Hints">
  If the AI's questions are all generic, you probably didn't paste enough code. Give it the component and one
  related file. If the plan has more than five steps, the ticket may be too big; ask the AI to split it. You'll
  often find a question you hadn't thought about, and a plan step you don't need.
</Answer>

## Remember

- AI-assisted: you do the work, AI helps. AI-native: AI drafts, you decide and check.
- Ask for questions and a plan before any code.
- Your job is the decisions and the review, and you can't skip either.
